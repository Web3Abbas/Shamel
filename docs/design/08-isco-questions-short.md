# Questions for ISCO — short list (English, copy-paste ready)

> Short form of [`08-isco-questions.md`](08-isco-questions.md) (which has the Arabic translation, the cover letter,
> sub-points, "why we ask" lines and traceability). Every question was checked against ISCO's own API manual on
> 2026-11-03: points the manual already answers were removed, and points it only partly covers quote the manual
> (page numbers refer to the manual PDF). Numbering here is sequential and differs from the ISCO-nn ids.

```
QUESTIONS ABOUT THE SHAMEL PRO WEB API

AUTHENTICATION AND SESSIONS
1. After a successful /Main/Login, how long does the token stay valid? Is there a fixed lifetime, an idle timeout, or both, and can they be configured? Is the lifetime extended each time the token is used?
2. If the same user logs in again (from the API, the desktop program or another device), does the earlier token stop working? How many concurrent sessions may one user have? Is a token bound to the client's IP address? Do tokens survive a server or application restart?
3. The manual documents no logout endpoint. Is there one? Does changing a user's password, disabling the user or removing their API permission immediately invalidate tokens that were already issued?
4. The manual uses the name "username" for both the login form field and the request header (p. 4), while p. 2 calls it "رقم المستخدم" (user number). Please confirm the header must carry exactly the login name sent to /Main/Login, not userCode or userId.
5. The manual says every error returns HTTP 500 with the error details, and AuthResult has a "success" field (p. 4). For a wrong password, an unknown user, a disabled user and a locked user, which happens: HTTP 200 with success=false, or HTTP 500? Please give an example body for each. Is there an account-lockout policy after repeated failed logins?
6. Are API users the same accounts as Shamel desktop users? Can API access be enabled or disabled per user, and can we create an API-only user that cannot sign in to the desktop program?
7. Apart from the salesman scoping the manual describes (GetCustomers with getAll, p. 7; GetDelivery, p. 16), does the API enforce other user permissions defined in Shamel (read-only, allowed voucher types, allowed stores, hidden cost prices)? If yes, which apply to which endpoints?

TRANSPORT SECURITY AND HOSTING
8. Does the Shamel Web API support HTTPS? Which certificates (public CA, internal or self-signed) and TLS versions (1.2, 1.3) are supported, and can plain HTTP be disabled?
9. The manual describes only Shamel's own authentication (login, then the username and token headers; pp. 2 and 4). If the API is hosted in IIS, please confirm no IIS-level authentication (Windows/NTLM, Basic, client certificates) is enabled or required by default, and whether you recommend any of them.
10. What is the API's default base address (host, port, virtual directory)? Can it be bound to localhost only or restricted by IP without breaking anything? Does anything else (desktop program, mobile apps) need to reach it over the LAN? Must it run on the same server as the Shamel database?
11. Does Shamel or its web server log request headers or bodies (which would include the token, and the password at login)? Where, for how long, and can this be disabled or masked?
12. Which network services must stay reachable on the Shamel server (SQL Server, file shares, remote desktop, licensing)? Do you have a recommended firewall configuration or hardening guide?
13. How are security fixes for Shamel and its Web API delivered, and how often? The manual lists general contacts (info@iscosoft.com, +970 9 2373001; p. 1). Should suspected vulnerabilities go there, or is there a dedicated security contact? Do you publish security advisories?
14. GetVoucher uses a header with an underscore (voucher_code), which many proxies drop. Is there an alternative name or a query-string form? Is there a size limit for header values such as "filters", and for the "obj" form posts? Are gzip compression and keep-alive connections supported? Apart from the endpoints in the manual, does the API site expose other endpoints (older versions, update/delete, admin, help or Swagger pages)? Do any of them change data or answer without a valid token, and can they be blocked?

REQUEST AND RESPONSE CONVENTIONS
15. The manual says "post parameter" for 7 endpoints (/Main/Login, /Customer/Post, /Item/Post, /Voucher/Post2, /CostCenter/Post, /Report/GetAccountsheet and /CostCenter/GetCostCenterAccountsheet), so we use POST for those. For the other 23 endpoints it names no method: please confirm GET or POST for each, and whether other methods are rejected.
16. The manual spells the same parameter differently: itemCode (GetItems, getItemDetails), itemcode (GetItemsStores) and ItemCode (GetLastPriceReport). Are header names case-sensitive? Are URL paths case-sensitive (the manual prints /Item/getItemDetails with a lower-case g)? Four paths are printed without a leading slash (p. 16-17) - is that only a typo?
17. The manual shows the value "true" for getBalance, getStopped, getClassifications, getContacts, getAll and getCustomerBalance, and says for getCustomerBalance that "If the header is not set or set to false, 0 is returned" (p. 7, 17). Are other spellings (True, TRUE, 1) accepted, and does an absent header mean false for the other boolean headers too? The manual says an empty lastupdatedate or customerCode returns everything (p. 7-9): does an absent header give the same result, and does this hold for the other optional headers? How should Arabic values be sent in headers? The writes return their result "as Json" (p. 9): is every response, including reads and errors, JSON encoded as UTF-8?
18. The manual says "code" returns "one customer with the filled code" and that the item and serial filters return records "with this ... only" (p. 7-11). Is matching exact for all filters (including vatreg, customerCode, barcode and itemcode/ItemCode), or by prefix or partial? Is it case-sensitive, and are surrounding spaces trimmed? Can "code" ever return more than one record?
19. The manual specifies x-www-form-urlencoded only for /Main/Login; the other posts take "a post parameter with key name [obj]" (or [filters]). Does the same content type apply to them, and which encoding is expected (UTF-8)? Is multipart/form-data or a raw JSON body also accepted? Are JSON property names inside obj case-sensitive (the classes mix Name/VatReg with customer_code)? Are unknown properties ignored or rejected? The classes declare numbers as int or double - are numeric strings (e.g. "10.5") also accepted?
20. The manual shows only C# classes, never a JSON sample. Are response property names exactly as in those classes (same case, e.g. VATReg, sale_parice1)? For empty values, do you return null, "", 0 or omit the field? Is the field order stable? Are amounts rounded to fixed decimals? Do all endpoints always return JSON and never XML, whatever Accept header is sent, and is the Content-Type always application/json?

ERRORS
21. The manual says every error returns HTTP 500 "with the error details" (p. 4). What is the exact format of the error body? Are there stable error codes? What exactly is returned when the token has expired or is invalid? Is any other status code ever returned (400, 401, 404, 405) - for example for an unknown path, a wrong method or a missing token?
22. The manual says any error returns HTTP 500, yet write results carry Success and ErrorMessage (p. 4, 9, 15). When does a write return HTTP 200 with Success=false, and when HTTP 500? In /Voucher/Post2, does ErrorMessage (a list) contain one entry per problem? Could you share the list of validation messages (unknown customer, unknown item, stopped customer, insufficient stock, duplicate code, closed period)?

LOAD, LIMITS AND LARGE RESPONSES
23. Does the API enforce any rate or concurrency limit (per user, per IP, global)? What is the recommended maximum number of parallel requests and requests per minute? Do heavy reads (full item or customer lists) slow down desktop users or lock tables? Which endpoints are expensive? What is the server-side request timeout?
24. The manual describes the list endpoints as returning "all" records and documents a fixed limit only for GetCurrencyRates ("latest 10"). Please confirm there is no other maximum row count or truncation on large results. Are there undocumented paging, limit, sort or field-selection parameters? Is there a maximum date range for fromDate/toDate?

INCREMENTAL SYNC, DATES AND CHANGE DETECTION
25. The manual says dates are always yyyy-MM-dd (p. 4) and that GetCustomers and GetItems return records "updated after lastupdatedate" (p. 7, p. 9). Does lastupdatedate also accept a time part? Is a record changed on the same day returned (is the comparison > or >=)? Which timezone is used? Which changes update a customer's or item's last-update value? For GetItemsStores the manual lists the lastupdatedate header (p. 10) without explaining it - what does it filter there? How are deleted records reported?
26. Can customers, items and vouchers be deleted or edited after saving or posting (the API documents only inserts)? Can deletions be detected through the API? VoucherHeader.update_date has no description (p. 13): does it change on every edit (header or lines), does it have a time part, and in which timezone? Does GetVouchers filter by voucher date or by entry/update date?
27. Which timezone do the server and database use for business dates (we assume local Palestine time)? Are fromDate and toDate inclusive in GetVouchers, GetExtraVouchers and both account-statement reports? The manual gives VoucherHeader.time as "hhmmss" (p. 13); please confirm the hour is 24-hour (00-23).

SALESMAN SCOPING
28. We understand that a user linked to a salesman sees only that salesman's customers in GetCustomers unless getAll=true is sent (p. 7), and that GetDelivery returns the delivery prepared for the salesman (p. 16). Is that correct? Which other endpoints apply salesman scoping (balances, prices, vouchers, reports)? What does a user with no salesman link see? Does getAll require a special permission?

MASTER DATA
29. The manual prints only the heading of /Files/GetSalesmen (p. 6). What does it return (fields and types), and does it return all salesmen or only the logged-in user's?
30. The manual lists the store fields id, name, type, car_code and orgnization_code (p. 6, under a class named City). Please explain what "type" (and its values), "car_code" and "orgnization_code" mean.
31. What do Currency.units, Currency.division and is_base mean? The manual describes VoucherHeader.currency as the currency code, e.g. "NIS", "$" (p. 13); please confirm this is Currency.code from GetCurrencies, that it never changes, and that the same code is used in every other currency field. GetCurrencyRates returns the "latest 10 currency rate" (p. 5): 10 in total or 10 per currency? Is there a way to get historical rates or the rate on a given date?
32. The manual says there are 6 price classes (p. 6). Please confirm PriceClass id N (1-6) corresponds to Item.sale_pariceN and to Customer.price_class. What is the difference between sale_pariceN and unit_price_N? Is currN linked to price class N or unit N? Why is Customer.price_class a decimal? What does purchase_price represent?

CUSTOMERS
33. getStopped="true" returns only stopped customers (p. 7). When the header is absent, does GetCustomers return active and stopped customers, or active only? How can we get all customers in one call?
34. getBalance="true" returns the current, unpaid-cheques and returned-cheques balances (p. 7). What do these fields contain when getBalance is not sent - 0, and if so how do we tell a real 0 from "not requested"? Does "balance" already include the cheque balances and unposted vouchers? In GetCustomerBalances, is there one row per customer per currency, and what do pos, date and rate mean? GetVoucher gives the balance "at the invoice time" while GetVouchers says "excluding the invoice itself" (p. 17-18): does GetVoucher's balance include the voucher itself, in which currency, and in which field?
35. Please explain these customer read fields: citizen_code, attr, man_name, trans_permissions, level, creditType, discount (percentage or amount?), referee1, referee2, id_number. The /Customer/Post comments (p. 9) describe Address as street, Street as street 2, PhoneNumber as phone 1, Referee as referee 1, RefereeMobile as referee 1's phone, CustomerLevel as customer level: which read field is each returned in? Is RefereeMobile returned in referee2? MobileNumber is commented as "fax" (p. 9): is it the mobile or the fax number, and where does it appear when reading customers?
36. For Customer/GetCustomerPricesAsRows: which inputs does it accept, and does it return a list or a single object (the manual says "the following object", p. 16)? What do code, discount_type (its values) and tax (rate or amount?) mean? Is stock_code the item code? Are rows with an empty customer_code price-class prices (identified by price_class_name)?

ITEMS, STOCK AND CATALOG
37. ItemCatalog.image_path (p. 11): does it contain a URL, a local file path or a network path? If a URL, which server serves the images and does it need the same username and token headers? The only documented image endpoint, GetItemsCatalog ("Get all items image"), returns item_code and image_path strings - is there any endpoint that returns an item's image bytes? Which image formats and sizes should we expect?
38. The manual says the store header returns "items with this store only" and the model header "items with this model only" (p. 9). Item/Post has an int model (p. 20), but the Item read class has no model field. Does "store" select items with stock in that store or items linked to it? Does "model" take the numeric model id used in Item/Post? Does "serial" match ItemSerial.serial? ItemGroup.code says "Item has itemGroupCode field that refer to this field" (p. 11), but Item has item_group_code and item_group_father_code - please confirm item_group_code links to ItemGroup.code and parentCode to item_group_father_code.
39. ItemStore has a main_unit field next to qnty (p. 11); please confirm qnty is expressed in that unit. Are rows with zero or negative quantity returned? Is reserved or ordered stock included? GetItemsStores documents only the lastupdatedate and itemcode headers (p. 10) - is there a way to filter it by store?

REPORTS
40. GetLastPriceReport says both "ItemCode is mandatory" and "ItemCode is optional" next to the barcode header (p. 12) - which inputs are required, and which wins if both are sent? Each row carries a "customer" field: does the report cover all customers, and can it be filtered by customer? Is "customer" a code or a name? What do "code" and the row set mean (which voucher types, how many rows)?
41. The account statement's filter is named customerCode, while the overview calls this report "كشف حساب محاسبي" (p. 3, p. 12). Does customerCode accept any account code from the chart of accounts, or only customer codes? credit, debit and balance are strings (p. 13): what is their number format (decimal separator, negative sign, empty for zero)? What do start_date and type mean in each row? Is the opening balance returned as a separate first row?
42. For GetCostCenterAccountsheet (p. 19), what are the values of the "type" filter and what does "account" accept? The manual documents no endpoint that lists cost centers - is there one? /CostCenter/Post is described as "Insert new customer", but the overview lists "مركز تكلفة جديد" and the body is CostCenterDTO (p. 2, p. 18), so we read it as inserting a cost center - please confirm, and explain father, type (which values?) and date. /CostCenter/Post returns only Success and ErrorMessage (p. 19): is the created code always the code we send, and what happens if it already exists?

VOUCHERS: READING
43. GetVouchers is documented as "return array of Voucher", but the manual defines two Voucher classes - the full one under GetVoucher and the short one after GetExtraVouchers (p. 17-18). Which one does GetVouchers return? What is GetExtraVouchers for (what does "extra" mean) and which voucher types does it include? The filters have only customerCode and currencyCode (optional) plus fromDate and toDate - please confirm GetVouchers cannot filter by voucher type and that both dates are required. Must GetVoucher's voucher_code header be the full code including the type letter (e.g. I1234), as returned in refrenceId by Post2?
44. GetDelivery returns "the delivery that is prepared to the salesman" as one Voucher object, with no documented input (p. 16). Please confirm it always uses the logged-in user's salesman (salesmanCode from login). What is returned when there is no delivery, or several? Which voucher type is it? Does calling it change anything in Shamel (for example mark the delivery as taken)?
45. GetStatus documents only "Fill Header[manual]" and the status values 0-4 (p. 16). Please confirm it takes the order's manual_code (paper reference), not its voucher code. Is the response a bare number or JSON (what shape)? What is returned for an unknown value? Can several orders share one manual_code? Is there a way to get an order's status by voucher code? Does it apply only to orders (type 0), and what does it return for other types?

WRITES
46. Can a write still be saved even though the API returned HTTP 500 or timed out? Does Shamel reject a duplicate voucher code, manual_code, customer or item code? The manual documents no retry mechanism, and the only read by manual code is GetStatus (status only) - what is your recommended way to make a retry safe? Could we put our own unique reference in manual_code, and which endpoint would find a voucher by it?
47. VoucherHeader.system_id "value must be between 1000 and 2000" (p. 14). What does it mean, are 1000 and 2000 themselves allowed, and which value should an integration use (do we need to register one)? Is the value visible in Shamel, and is it returned by GetVoucher as stored at insert?
48. The prefix table (p. 15-16) has no letter for PurchaseDelivery (type 2) - which letter should it use, or must its code be left to Shamel? After the prefix, what format is allowed (digits only, maximum length, leading zeros)? Are codes unique per type, per year or globally? The manual says Shamel assigns a number when code is not sent (p. 13) - how does it number them (a series per type? per branch?), and can codes we send collide with that series?
49. The manual describes VoucherHeader.balance as "قيمة الفاتورة مع خصم الفاتورة" (p. 13): please confirm it is the total after the header discount, and whether it includes VAT. VoucherItems.vat is the tax for a quantity of 1 (p. 14): please confirm VoucherHeader.vat is the voucher's total tax. On insert, does Shamel compute tax and totals itself or keep the values we send? Must balance, vat and cheq_balance be sent? is_posted and is_printed decide whether the voucher is entered as posted or printed (p. 13): what does an unposted voucher do in Shamel (balances, stock, posting later), and do you recommend is_posted=false so an accountant can review it first?
50. accounts is "mandatory in journal vouchers only" (p. 13) - is it also allowed in other voucher types? Cheques go in cheqs with their total in cheq_balance (p. 14): for receipts (24) and payments (27), where does the cash amount go, and must balance equal cash plus cheq_balance? The overview lists "فاتورة من ارسالية" (p. 3) but VoucherTypes has no such entry - is it a SalesInvoice (9) with delivery_id/delivery_pos? How is the destination store given for an internal delivery (16)? Beyond the manual's notes (accounts in journals only; voucher_code and name not filled; measure, color and serials unused), which header and line fields are required for each type? Does Shamel check stock availability, credit limits and stopped customers or items on insert? Type 5 is "مردود من ارسالية برسم البيع" (p. 15) - when should it be used instead of a sales return (4)?
51. /Customer/Post has no code field and returns the inserted code in value (p. 9): please confirm Shamel always generates it, and say which currency, credit limit and discount a new customer gets. /Item/Post takes our own code (p. 20): what does its "value" contain? Which item "type" values are allowed, and which values are expected in "currency" and "group"? Where can we read the valid values of trademark, producing_company, style and model?
52. Please list the possible values and meanings of these coded fields: Store.type; Customer.creditType, attr, trans_permissions, level; CustomerContact.type (is typeName its label?); Item.type, eval_unit, and the int flags stopped/paused/has_serial/has_measure/has_color/has_expiry (0/1?); ItemSerial.status; VoucherHeader.payment_type; VoucherItems.unit (an index into unit1-unit6?); VoucherAccounts.debit_credit; GetExtraVouchers cr_dr; GetCustomerPricesAsRows discount_type; the "type" column of both account statements; the cost-center "type" filter and CostCenterDTO.type. VoucherTypes lists only 0, 2, 4, 5, 9, 10, 12, 16, 22, 23, 24, 27, 28 (p. 15): do numbers 1, 3, 6-8, 11, 13-15, 17-21, 25 and 26 exist, and what are they?
53. Which versions of Shamel and its Web API do we have, and how can we read the version? Does our manual (which has no version number or date) match it, and is there a newer one? Is there a changelog, and how much notice is given before breaking changes? The manual documents only /Voucher/Post2 - does an older /Voucher/Post exist, and should we use Post2 only? Which IIS/.NET versions does the API require? Can you provide a test company or a copy of our database to test writes safely, and is there a licence cost for it?
54. The manual says any error returns HTTP 500 with details, while writes also return Success/ErrorMessage (p. 4, 9, 15). If a write (/Voucher/Post2, /Customer/Post, /Item/Post, /CostCenter/Post) is sent with an expired or invalid token, is the token always checked before anything executes? Can an authentication failure happen after a write was partly or fully saved? What exactly is returned in that case, and is it the same as on a read?
55. Can we request new endpoints or changes, and what are the process, cost and timeline? These would help most (tell us if any already exist): pagination and a total count on large lists; lookup lists for GL accounts, cost centers, towns, payment terms, customer classifications, item types, trademarks, styles and models; a change feed that includes deletions or a date-and-time lastupdatedate (the manual's is date-only, on customers, items and stock only); update/cancel endpoints (the manual documents inserts only); a voucher-type filter on GetVouchers and a voucher lookup by manual_code (GetStatus accepts manual but returns only the status); an endpoint that returns item image bytes. Besides the general contacts in the manual, who is our technical contact for API questions, and what is the support channel?
56. Do the Shamel licence terms allow us to build and operate an internal integration layer (gateway) that calls the Shamel Web API for our own internal tools, and under which conditions? Is the API licensed per user or per connection, and does the one Shamel account our layer uses need a specific licence or extra fees? Later, not now, we may wish to offer this layer to other Shamel customers; would ISCO allow this, and under what conditions? May our documentation say it works with Shamel?
```
