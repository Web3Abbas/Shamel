12Performance

Always live, and still fast

You chose always-live data, so Bawaba never serves stale figures. It saves work in only two safe ways: identical simultaneous requests share one live call, and a 60-second snapshot keeps the pages of one list consistent.

Request coalescing

Only merged when the Shamel identity and the request are identical, so one token can never receive data meant for another.

Pagination snapshots

Shamel returns whole lists at once; Bawaba pages, filters, sorts and searches that one fetch, with Arabic-aware search.

Why hardware stays the only limit

  • Stateless Go nodes: add nodes to scale, no sticky sessions
  • Streaming JSON: huge lists are processed record by record, so memory doesn’t grow with list size
  • Permissions compiled in memory and audit written in background batches: no database round-trip on reads

Protecting Shamel itself

  • A global cap on simultaneous Shamel calls: requests queue instead of overloading the server
  • Circuit breaker when Shamel is down or slow
  • Retries only on safe reads; one shared re-login when Shamel’s session expires

13Audit log

Record everything, store very little

You asked for a full audit: every request and response, encrypted. Recording that naively would grow by terabytes. Bawaba stores each unique piece of content once, splits large lists into chunks so that a changed list only stores its changed parts, then compresses and encrypts.

14Webhooks & guidance

Changes come to you, and the API coaches its callers

Shamel can’t push changes, so Bawaba checks for them every 5 minutes, only for events someone has subscribed to, and delivers signed webhooks. Each response also tells the calling tool, often written by an AI, how to behave better.

Webhook events

customer.createdcustomer.updatedcustomer.removedcustomer.balance_changed item.createditem.updateditem.removedstock.changed voucher.createdvoucher.updatedvoucher.removedorder.status_changed
  • Signed with HMAC-SHA256 (Bawaba-Signature), with a timestamp to block replays
  • Retries with backoff for about 38 hours, then a dead-letter queue you can replay
  • Filtered by the subscribing token’s current permissions and hidden fields
  • Optional pull mode for tools without a public endpoint

How changes are detected

Customers, itemsShamel’s lastupdatedate with overlap windows + record hashes; daily full reconciliation
Stock, balancesDiff of the full snapshot
VouchersTiered date-range scans
Order statusStatus checks for tracked orders

Only one node polls each stream (leader lease), so adding nodes never multiplies the load on Shamel.
