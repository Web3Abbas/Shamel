01At a glance

One secure door in front of Shamel

Today every integration logs into Shamel with a real Shamel username and password and can see whatever that user sees. Bawaba becomes the only way in: each tool gets its own token with exactly the access it needs, and Shamel itself disappears from the internet.

“Make as many API tokens as I want, more security and permissions, expand the API, better documentation — and a firewall so no hacker can get to Shamel or even find it.”

Origin-hiding firewall

Shamel’s IP, host, version and raw errors never leave Bawaba. Cloudflare in front, an outbound-only Connector behind.

Tokens & permissions

Scopes per resource, per voucher type, data scoping (stores, salesmen, customers…) and field hiding. Read-only and write-only presets.

Safe for AI builders

AI agents only ever talk to Bawaba. They can request access; nothing goes live until you approve it on the server. Sandbox with fake data.

A better API

Clean /v1 REST with real status codes, paging, search, combined endpoints, webhooks and idempotent writes — plus a legacy-compatible mode.

Built for load

Go, stateless nodes, streaming JSON, request coalescing. Always-live data; the hardware should be the only bottleneck.

Full audit, optimized

Every call recorded in full, encrypted — with de-duplication and compression so storage stays small.

02Why a gateway

Shamel’s API today vs. with Bawaba

Shamel Pro’s Web API works, but it was built for one trusted integration, not for many tools with different needs. Bawaba keeps Shamel exactly as it is and fixes everything around it.

TopicShamel API todayWith Bawaba
CredentialsOne real Shamel username + password per integration; token from /Main/LoginUnlimited Bawaba tokens; Shamel credentials stay encrypted inside Bawaba and are never shared
PermissionsOnly Shamel’s own salesman scoping; getAll=true sees everythingScopes, voucher-type rights, data scoping and field hiding per token; deny by default
ExposureShamel server must be reachable by every integrationShamel reachable only by Bawaba — through an outbound Connector tunnel (no open ports) or an IP-locked direct URL
ErrorsEvery error is HTTP 500 with raw details (can leak internals)Proper status codes and stable error codes in English + Arabic; internals only in the encrypted audit log
ParametersFilters passed as HTTP headers; writes as a JSON string inside a form field (obj=)Query parameters and JSON bodies, validated against a strict schema
Large listsEverything returned at once, no pagingCursor paging over a 60-second snapshot, search (Arabic-aware), sorting
NamingTypos and inconsistencies (sale_parice1, orgnization_code, refrenceId)Consistent snake_case with typos fixed, documented in OpenAPI 3.1
DuplicatesA retried request can post the same invoice twiceIdempotency-Key on every write; optional human approval queue
Change trackingClients must poll and diff themselvesSigned webhooks (customers, items, stock, vouchers, order status)
VisibilityNo usage or audit trailPer-token analytics, full encrypted audit, e-mail alerts
DocumentationA 20-page PDFInteractive bilingual docs, error catalogue, llms.txt for AI agents, sandbox
i
Nothing changes inside Shamel. Bawaba is a separate layer: Shamel keeps running exactly as today, and existing integrations can migrate gradually by switching to Bawaba’s legacy-compatible paths (same requests, new URL and token).

03Architecture

How the pieces fit together

Every request enters through Cloudflare, passes Bawaba’s pipeline, and reaches Shamel only through the Connector’s outbound tunnel. The admin side is bound to the server itself and has no public route.

request pathConnector tunnel (initiated from the Shamel site)blocked

Data plane

Stateless Go nodes behind Cloudflare. Add nodes to scale; any node can serve any request.

Control plane

Bound to 127.0.0.1; you reach it through an SSH tunnel. Approvals and live-token creation happen only here.

Connector

Small service next to Shamel that dials out to Bawaba. Shamel needs no public IP and no open port.
