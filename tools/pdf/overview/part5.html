15Running Bawaba

Dashboard for you, CLI for you and your AI

The bilingual dashboard (Arabic / English, full RTL) runs only on the server, and you reach it through an SSH tunnel. The bawaba CLI does everything the dashboard does, prints JSON for scripts, and has a restricted remote mode that AI agents use with their agent token.

Local owner mode

On the server · all commands

Root-only Unix socket (sudo bawaba …). Approvals, firewall rules, live tokens, keys, audit decryption. These commands don’t exist anywhere else.

Remote agent mode

Anywhere · agent token over HTTPS

Only agent-safe commands: read docs and the OpenAPI spec, check your own token and usage, request access, make test calls, manage the agent’s own webhooks.

# AI agent, on its own machine $ bawaba request-token \ --scopes customers:read,stock:read \ --env test --reason "stock dashboard" \ --wait ✓ request ar_19 filed · pending owner # owner, on the server $ sudo bawaba access-request list ar_19 dash-builder customers:read stock:read test $ sudo bawaba access-request approve ar_19 ✓ approved · secret can be collected once
# owner, on the server $ sudo bawaba token create \ --name sales-dashboard --env live \ --preset read-only --data-scope store=1,2 \ --hide-fields items.purchase_price \ --ip-allow 203.0.113.0/28 --json {"id":"tok_8k2","secret":"bwb_live_…"} $ sudo bawaba firewall explain 198.51.100.7 banned · auto: auth_failure · 24h $ sudo bawaba audit search \ --token tok_8k2 --since 1h

16Deployment

Three ways to run it, one codebase

Hosting is still to be decided, so Bawaba ships as Docker Compose bundles and standalone binaries. The gateway runs on Linux; the Connector also runs as a Windows service, since Shamel usually lives on a Windows server.

Recommended

A · Cloud VPS + Connector

  • Two layers of hiding: Cloudflare hides the VPS, the tunnel hides Shamel
  • No changes to the office network
  • Easy to back up and scale up
Simple

B · One box in the office

  • Everything on one Linux machine next to Shamel
  • Exposed only through a Cloudflare Tunnel
  • Good when you have a spare server
Scale

C · Scaled-out cluster

  • Identical stateless data nodes; scale by CPU
  • Separate small control node, not behind the LB
  • Rolling upgrades with draining

Backups

Encrypted PostgreSQL archives (7 daily, 4 weekly, 12 monthly) and incremental blob sync. Monthly restore drills are tracked.

Master key backup

Kept separately from data backups: paper export or 2-of-3 shares. Bawaba nags you until a backup is verified.

Upgrades

Versioned schema migrations; gateway nodes drain and restart one at a time with zero downtime.
