15Running Bawaba

Dashboard for you, CLI for you and your AI

The bilingual dashboard (Arabic / English, full RTL) runs only on the server, and you reach it through an SSH tunnel. The bawaba CLI does everything the dashboard does, prints JSON for scripts, and has a restricted remote mode that AI agents use with their agent token.

Local owner mode

On the server · all commands

Root-only Unix socket (sudo bawaba …) or bawaba login with password + TOTP. Approvals, firewall rules, live tokens, keys, audit decryption. None of these exist in remote mode.

Remote agent mode

Anywhere · agent token over HTTPS

Only agent-safe commands: read docs and the OpenAPI spec, check its own token and usage, request access, make API calls within its own scopes, manage its own webhooks (if granted).

# AI agent, on its own machine $ bawaba request-token \ --scopes customers:read,stock:read \ --env test --reason "stock dashboard" \ --wait ✓ request areq_19 filed · pending owner # owner, on the server $ sudo bawaba access-request list areq_19 dash-builder customers:read stock:read test $ sudo bawaba access-request approve areq_19 ✓ approved · secret can be collected once
# owner, on the server $ sudo bawaba token create --kind tool \ --name sales-dashboard --env live \ --preset read_only --data-scope store=1,2 \ --hide-fields items.purchase_price \ --ip-allow 203.0.113.0/28 --json {"data":{"id":"tok_01JBX4…","token":"bwb_live_…"},"meta":{}} $ sudo bawaba firewall explain 198.51.100.7 banned · auto: auth_failure · 24h $ sudo bawaba audit search \ --token tok_01JBX4… --since 1h

16Deployment

Three ways to run it, one codebase

Hosting is still to be decided, so Bawaba ships as Docker Compose bundles and standalone binaries. The gateway runs on Linux; the Connector also runs as a Windows service, since Shamel likely runs on a Windows server.

Recommended

A · Cloud VPS + Connector

  • Two layers of hiding: Cloudflare hides the VPS, the tunnel hides Shamel
  • Shamel passwords stay at the office, with the Connector
  • No office network changes; easy to back up
Simple

B · One box in the office

  • Everything on one Linux machine next to Shamel
  • Exposed only through a Cloudflare Tunnel
  • Depends on office power and internet; needs an off-site backup
Scale

C · Scaled-out cluster

  • Identical stateless data nodes; scale by CPU
  • Separate small control node, reached only by SSH
  • Rolling upgrades with draining

Backups

Encrypted PostgreSQL archives (7 daily, 4 weekly, 12 monthly) and incremental blob sync. Monthly restore drills are tracked.

Master key backup

Only master.key needs one (data.key is re-issued from it): paper export or 2-of-3 shares, kept apart from data backups.

Upgrades

Expand/contract migrations; cluster nodes drain one at a time with zero downtime (a plain single-box restart costs seconds).
