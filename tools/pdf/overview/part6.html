17Delivery plan

Reads first, then writes, then scale

As you asked, everything that reads data comes first. AI agents can start building against the sandbox partway through M1, your first tools go live in a restricted pilot, and writes and webhooks follow in parallel.

M0

Foundations

Repo, CI with the leak suite, config, two key files, Postgres/Valkey/blob wiring, mock Shamel with Arabic data, OpenAPI skeleton, Docker bundles

Exit: GET /v1/currencies through all 17 pipeline stages
M1

Read API

Every read endpoint, tokens & permissions, firewall, origin hiding, snapshots, Arabic search, full audit, Connector, CLI, dashboard, docs, alerts

Exit: leak suite clean, pentest round 1 with no open critical/high
M2

Writes

Write endpoints for all 13 voucher types, idempotency, approval queue, batches, legacy writes, AI access requests

Exit: 0 duplicates in 10,000 fault-injected writes
M3

Expansions

Webhooks engine and API, usage analytics UI, remaining alerts, Grafana bundles

Exit: no polling without subscribers; no lost events
M4

Hardening

Load tests against the targets, chaos tests for every failure mode, cluster topology, pentest round 2, restore drills

Exit: all performance targets met on the reference node

Milestone 1 ships in three steps

Step 1

Sandbox reads (α)

AI agents start building your read tools with bwb_test_ tokens against fake data.

Step 2

Live read pilot (β)

Your first tools on real data, with live tokens locked to your own IP addresses, for at least 14 days.

Step 3

All reads live (GA)

After the pilot and the first pentest. The API contract is frozen at version 1.0.0.
