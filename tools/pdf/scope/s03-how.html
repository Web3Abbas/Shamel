02How the API works

Log in, then headers on every call

The Shamel Pro Web API is a small HTTP API published by ISCO next to the Shamel accounting program. You log in with a Shamel username and password, receive a token, and send it with your username on every later request. Read filters travel in HTTP headers (the account statements use a form field), and new records are posted as a JSON string inside a form field.

Filters are headers

Options such as code, itemCode, getBalance or filters (a JSON object) are sent as HTTP headers, not as URL parameters (p. 4–18).

Writes are form posts

The four write endpoints take a form field named obj holding a JSON string of the record (p. 8–20). The manual says “post parameter” for 7 endpoints in total.

Dates and sync

“Date format is always yyyy-MM-dd” (p. 4). Customers and items return records “updated after” lastupdatedate; the stock endpoint takes the same header, effect unstated.

Salesman scoping

Login returns the user’s salesmanCode; customer lists are limited to that salesman unless getAll=true is sent (p. 4, 7).

Errors

“Any error occurred the service will return Http error 500 with the error details” (p. 4); write results also carry Success and ErrorMessage.

What the manual leaves out

No base URL, HTTPS, token lifetime, rate limits, paging, versioning or HTTP methods for 23 endpoints. These are in the ISCO question list.
